# STE KB errata

Transcription notes from distilling `extensions/ste/STOS_STE.DOC` (Asa Burrows) plus the supplementary material in `extensions/ste/Docs/`: `STE_DAC.doc` (DAC/microwire tutorial), `STE_1.doc` and `STE_2.doc` (J.J./Jens Hucke's STOSSER columns, which also cover the separate BLITTER extension), `HARD1STE.DOC` (Hucke's hardware-scrolling follow-up column), `STE_EXT2.doc` (worked examples for E PALETTE, E COLOUR, E COLOR, STE and LIGHT X/LIGHT Y), and `STEING.doc` (TEZ Pearson's DAC guide, which states DAC SPEED n = 0-3, corroborating the tutorial side of the speed conflict). All sources are Atari extended-ASCII/CRLF, converted to plain ASCII.

- STE: doc writes the function as `x = STE` with no parentheses, unlike the extension's other functions (`x= LSTICK (j)`); kept verbatim.
- LIGHT X/LIGHT Y: doc syntax line reads `x =LIGHT X and y =LIGHT Y` (combined, no space after `=`); split into two entries and spaced normally.
- LIGHT X/LIGHT Y: doc contains a garbled duplicated sentence — "You can check the button using the FSTICK (3) command because the To check the <fire> button use the FSTICK (3) command, the button is returned as joystick three." — condensed to a single statement.
- DAC SPEED: doc lists speeds 0=6Khz, 1=12.5Khz, 2=25Khz then "4 is a pretty amazing 50Khz", skipping 3; J.J.'s tutorial (STE_2.doc) lists 3=50 Khz, and TEZ Pearson's STEING.doc independently states n = 0-3 (0=6.25, 1=12.5, 2=25, 3=50 Khz). KB gives the range as 0-4 (the official doc's own listing), with the discrepancy flagged in the entry.
- DAC SPEED: the doc's syntax line has no parameter name ("DAC SPEED" alone, values described in the text); kept verbatim. The STE_DAC.doc raw-register listing also quotes slightly different frequencies (6.5/12.5/25.6/51.3 Khz) than the doc's 6/12.5/25/50.
- DAC volume ranges conflict: official doc says 0-12 for master, left, right, treble and bass; the STE_DAC.doc example uses `dac m volume 40` and left/right of 20; STE_2.doc states master is 0-40 and left/right 0-12. Official doc's 0-12 kept as authoritative in every entry; conflict flagged in each volume entry.
- HARD SCREEN SIZE: syntax includes a `mode` parameter that is never explained anywhere in the official doc; HARD1STE.DOC always passes 0 and punts on it too ("0 means 0 ? if you know please tell me"). Flagged in the entry.
- HARD PHYSIC: written as a function (`x = HARD PHYSIC (screen address)`) but described as "tells the ST where the screen is stored" — the official doc is unclear whether it sets or returns the address. Resolved by HARD1STE.DOC, which states "All it does is set the origin of the image data it will window onto": it is a setter, used in Hucke's sketch as `x=hard physic(logic)`; what `x` receives remains unexplained. Syntax transcribed verbatim.
- STICK1/STICK2: doc writes `x =STICK1` with no space after `=`; kept verbatim.
- Doc says "The DAC is one of the best things added to the ST" — means the STE; normalized in the dac.md intro.
- Scope boundary: STE_1.doc and STE_2.doc also document the separate BLITTER extension (BLIT CLS, BLIT COPY, BLIT SOURCE ADDRESS, etc. — see extensions/ste/Docs/blitter.txt). Those commands are a different extension and are deliberately not documented in this KB.
- Hardware scrolling: the official doc says registration (£10 to Asa Burrows) got you "a comprehensive manual with copious examples" — only this smaller doc survives. However the promised follow-up column DOES survive: `HARD1STE.DOC` (Jens Hucke, same STOSSER series) explains windowing onto a virtual screen, shows `HARD SCREEN SIZE w,h,0`, and gives a setup sketch (`reserve as work 14,640000` / `physic=start(14)` / `x=hard physic(logic):screen swap`). The named example programs (VERTICAL.BAS, HORIZON1.BAS, 4SCREENS.BAS, HSHORIZO.NEO) do not survive. HARD1STE.DOC also resolves the HARD PHYSIC set-vs-return question above. All incorporated into scrolling.md.
