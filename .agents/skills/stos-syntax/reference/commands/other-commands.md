# STOS commands: other-commands

## GOTO
`GOTO line` — Jump to a new line number.

- **line**: any line in your Basic program, or any allowable STOS Basic expression involving variables or constants (a computed goto).

GOTO is probably the most commonly used of all the Basic instructions. The action of a GOTO is to transfer the control of the program from the current line number to a new one. Two forms are available:

- `GOTO line number` — *line number* can be any line in your Basic program.
- `GOTO expression` — *expression* can be any allowable STOS Basic expression involving either variables or constants. Technically this is known as a computed goto.

### Example
```text
new
10 goto 30
20 print "This line is never printed"
30 print "Now executing line 30"
```
A computed GOTO:
```text
new
10 JUMP=10
20 goto JUMP*2+20 : rem same as goto 40
30 print "This line is never printed"
40 print "Jumped to line ",JUMP*2+20
```

### Gotchas
- Computed gotos are invariably far slower than normal ones, and make it almost impossible to renumber your program. They should be used with extreme caution; any mistake in the calculation could lead to your program jumping somewhere totally unforeseen.
- STOS Basic does not support any form of labels. You should remember to place a number at the start of each and every line (see AUTO).
- GOTOs should NEVER be used to jump inside a FOR...NEXT loop, as this will lead to a NEXT WITHOUT FOR error.

**See also:** ON GOTO

## GOSUB
`GOSUB line` — Jump to a subroutine.

- **line**: line number to jump to, or an expression evaluating to a line number.

This is very similar to GOTO, but has the additional bonus of enabling you to jump back where you started with a RETURN instruction. The most common use of GOSUB is to allow you to split a program into smaller, more manageable chunks, known as subroutines. As with GOTO, there are two different forms of the GOSUB instruction:

- `GOSUB line` — Jump to the subroutine at *line*.
- `GOSUB expression` — Jump to the subroutine at the number given by the result of *expression*.

### Example
```text
new
10 I=1
20 gosub 40
30 goto 20
40 print "You have called this gosub ";I;"times"
50 inc I
60 return
```

**See also:** ON GOSUB

## RETURN
`RETURN` — Return from a GOSUB to the next instruction.

RETURN exits from a subroutine, and jumps back to the statement after the initial GOSUB.

### Example
```text
new
10 gosub 100:print "Returned"
20 end
100 print "Inside Gosub":return
```

## POP
`POP` — Remove the RETURN information after a GOSUB.

The POP instruction removes the return address generated by a GOSUB and allows you to leave the subroutine without having to execute the final RETURN statement.

### Example
```text
new
10 I=1
20 gosub 40
30 goto 20
40 print "You have called this gosub ";I;"times"
50 inc I: if I>100 then pop:goto 70
60 return
70 print "Gosub terminated after ";I-1;" Times"
```

**See also:** ON GOSUB

## FOR...NEXT
`FOR var=start TO finish [STEP inc] ... NEXT [var]` — Repeat a section of code a specific number of times.

- **var**: the loop counter variable.
- **start**: initial value loaded into *var*.
- **finish**: terminal value tested against *var*.
- **inc**: optional increment (defaults to 1); may be negative.

When this loop is first entered, *var* is loaded with the value of *start*. The instructions between the FOR and the NEXT are now performed until the NEXT is reached. The NEXT instruction increments *var* by either *inc* or 1, depending on whether the optional STEP has been included. The loop counter is now tested. If *var* is either greater than *finish* (for positive increments), or less than *finish* (for negative steps), the loop is terminated and the instruction after the NEXT is executed. Otherwise the loop is restarted from the top.

### Example
A one-line direct-mode loop:
```text
for I=1 to 100 step 10:print I:next I
```
Printing the printable ASCII set:
```text
new
10 for a=32 to 255
20 print chr$(a);
30 next a
```
Nested loops drawing concentric ellipses:
```text
new
10 for R1=20 to 100 step 20
20 for R2=20 to 100 step 20
30 for a=0 to 3
40 ink a
50 ellipse 160,100,R1,R2
60 next a
70 next R2
80 next R1
```

### Gotchas
- STOS Basic will permit you to nest anything up to a maximum of 10 FOR...NEXTs in this way.
- Unlike some other Basics, STOS Basic does not allow you to replace lines 50-70 with `NEXT I,R1,R2`. All NEXT instructions should be placed directly at the correct point in the program.

## WHILE...WEND
`WHILE condition ... WEND` — Repeat a section of code while a condition is true.

- **condition**: any set of tests you like, and can include the constructions AND and OR.

This instruction enables you to repeat a series of instructions until a specific condition has been satisfied. The check is always performed at the start of the WHILE loop. The list of statements between the WHILE and the WEND will only be executed if this condition is true.

### Example
```text
new
10 input "Type in a number ";X
20 print "Counting to 11"
30 while X<11
40 inc X
50 print X
60 wend
70 print "Loop terminated"
```
The number of times the WHILE loop in this program will be executed depends on the value you input to the routine. If you type in a number larger than 10, you will find that the loop is not entered at all.

### Gotchas
- WHILE loops should only be used when a list of statements needs to be repeated 0 or more times.
- Each WHILE instruction in your program should be matched by exactly one WEND statement.

**See also:** REPEAT...UNTIL

## REPEAT...UNTIL
`REPEAT ... UNTIL condition` — Repeat a section of code until a condition is satisfied.

- **condition**: a list of conditions tested at the end of each iteration.

This pair of statements is similar to WHILE...WEND except that the test for completion is made at the end of the loop rather than the beginning. Furthermore, the action of the UNTIL statement is to continue executing the loop until the condition is FALSE.

### Example
```stos
10 repeat
20 M=mouse key : rem test to see if mouse button pressed
30 until M<>0
40 print "You clicked on the mouse button"
```

### Gotchas
- A REPEAT...UNTIL loop always executes at least once.
- Always remember to match each REPEAT with an UNTIL.

**See also:** WHILE...WEND

## STOP
`STOP` — Stop running the program and return to the Editor.

This command stops the current program running and returns to the editor. It can be used at any point in your program.

### Example
```text
new
10 input "Input a number between 1 and 100 (0 to stop)";N
20 if N=0 then stop
30 for I=1 to N
40 print I*I
50 next I
60 goto 10
```

### Gotchas
- Unlike END, a program terminated with STOP can be restarted with CONT, providing it has not been altered in the meantime using the editor.

## END
`END` — Exit from the program.

This instruction exits from a program and returns to the editor. Programs which have been terminated using END cannot be subsequently restarted using CONT.

**See also:** STOP

## IF...THEN...ELSE
`IF conditions THEN statements1 [ELSE statements2]` — Choose between alternative actions.

- **conditions**: any list of tests including AND and OR.
- **statements1**, **statements2**: either lists of STOS Basic instructions, or line numbers.

The IF...THEN instructions allow you to make decisions within a Basic program. The action of the IF...THEN instruction is to execute the instructions in *statements1* if the *conditions* are true. If the optional ELSE statement is included, then *statements2* will be performed when the *condition* is false. Otherwise control will pass to the line after the IF...THEN instruction. The following example program demonstrates most of the various possibilities.

### Example
```stos
10 input "Input a number";N
20 print "Number ";N;" is ",;
30 if N>0 then print "Positive"; else print "Negative";
40 if (N/2)*2=N then print " and Even" : goto 60
50 if (N/2)*2<>N then print " and Odd"
60 input "Continue Y or N";A$
70 if A$<>"Y" and A$<>"y" then 90 else 10
80 print "Never executed"
90 stop
```

### Gotchas
- STOS Basic restricts these IF...THEN statements to a single line.

**See also:** NOT, TRUE, FALSE

## ON...GOTO
`ON var GOTO line1,line2,line3...` — Jump to one of a list of lines depending on a variable.

- **var**: an integer variable holding a value between 1 and the number of possible destinations.
- **line1,line2,line3...**: the list of lines to jump to.

The ON GOTO instruction allows your program to jump to one of a number of lines depending on the value of the variable *var*. If *var* takes a value of 1, for instance, the instruction is identical to a simple GOTO *line1*. Similarly, if *var* holds a 2 then the program will branch to *line2*, and so on. In order to have an effect, the ON...GOTO statement requires *var* to hold a figure between 1 and the number of possible destinations.

### Example
```text
new
10 input "Input a number ";N
20 on N goto 50,60,70,80
30 print "You input a number either less than 0 or greater than 4"
40 goto 10
50 print "You input the number ONE" : goto 10
60 print "You input the number TWO" : goto 10
70 print "You input the number THREE" : goto 10
80 print "You input the number FOUR" : goto 10
```

### Gotchas
- The variable used for N must always be an integer.

**See also:** GOTO, GOSUB, ON GOSUB

## ON...GOSUB
`ON var GOSUB line1,line2,line3...` — GOSUB one of a list of routines depending on a var.

This is identical to ON...GOTO except that it uses a gosub rather than a goto to jump to the line. When the subroutine has finished executing, it should use a RETURN to jump back to the next instruction after the ON...GOSUB statement.

### Example
```text
new
10 input "Input a number ";N
20 on N gosub 50,60,70
40 goto 10
50 print "Subroutine ONE" : return
60 print "Subroutine TWO" : return
70 print "Subroutine THREE" : return
```

**See also:** GOSUB, ON GOTO

## ON ERROR GOTO
`ON ERROR GOTO line` — Trap an error within a Basic program.

- **line**: the location of a routine which will be executed whenever an error occurs. Can also be an expression, but this is generally a bad idea as the expression is only evaluated once, when the ON ERROR GOTO instruction is first initialised.

This command is used to allow the detection and correction of errors which occur within a STOS Basic program. For example, asking for the square root of a negative number generates `ILLEGAL NEGATIVE OPERAND` and returns you to the editor. You can avoid this problem by trapping the error with an ON ERROR GOTO instruction.

### Example
```stos
10 on error goto 50
20 input "Input a positive number";N
30 print "The square root of ";N;" is ";sqr(N)
40 goto 10
50 print
60 print "I'm afraid you can only take the square root of a positive number"
70 N=abs(N)
80 resume 10
```

To turn the action of ON ERROR GOTO off, type `ON ERROR GOTO 0`.

**See also:** RESUME, ERRN, ERRL, ERROR

## RESUME
`RESUME [NEXT|line]` — Resume execution of the program after an error.

This instruction is used from within an error trap created by ON ERROR GOTO. The action of RESUME is to jump back to the part of the program which caused the problem, after the error has been corrected by your routine. Three formats are available:

- `RESUME` — Jump back to the statement which caused the error and try again.
- `RESUME NEXT` — Jump to the statement following the one which generated the error.
- `RESUME line` — Jump to *line number*.

### Gotchas
- You should NEVER attempt to use GOTO in this context.

**See also:** ON ERROR GOTO, ERROR, ERRL, ERRN

## ERRN
`ERRN` — Reserved variable containing the number of the last error.

When an error occurs, ERRN is automatically loaded with the error number. This can be printed out using a line such as:

```text
print errn
```

**See also:** ERRL, ERROR, ON ERROR GOTO

## ERRL
`ERRL` — Reserved variable holding the location of the last error.

ERRL contains the line number of the last error which occurred.

### Example
```stos
10 rem Error test routine
20 on error goto 50
30 rem I appear to have made a slight mistake!
40 stop
50 print "ERROR NUMBER ";errn;" at line ";errl
60 resume next
```

**See also:** ERRN, ERROR, ON ERROR GOTO

## ERROR
`ERROR n` — Generate an error and return to the STOS Editor.

- **n**: the error number to generate.

The action of the ERROR command is to actually generate an error. This may sound rather crazy, but it's often quite useful. Supposing you have created a nice little error handling routine which is able to cope with any possible disc errors.

### Example
```text
error 2
```
Quits the program and prints out an out of memory error.

The most common form of this instruction is:
```text
error errn
```
This uses the ERRN function to print the current error condition. By testing the ERRN for the errors your program can correct, you only need to revert back to the editor when absolutely necessary.

**See also:** ON ERROR GOTO, RESUME, ERRN, ERRL

## BREAK
`BREAK ON | OFF` — Turn on or off the Control+C Break key.

Normally you can interrupt a program and return to the editor at any time by pressing the two keys Control and C. Although this is useful when you're debugging a program, it would be very dangerous to allow this function to operate in a commercial games program, as it would make it extremely easy for an unscrupulous person to steal some of your code. You can therefore turn this function off using `BREAK OFF` and reactivate it using `BREAK ON`.

### Example
```text
break on
```

### Gotchas
- NEVER run a protected program unless you have made a backup copy on the disc first. Otherwise if the program gets stuck in a loop, you could easily end up losing several hours of your work.

## KEY
`KEY(x)=a$` — Assign a string to a function key.

- **x**: key number, from 1 to 20. Numbers 11-20 represent shifted versions of the normal function keys.
- **a$**: the string (up to 64 characters) which will be returned whenever key *x* is pressed.

Any of the 10 function keys can be assigned a string of up to 64 characters long using the KEY command.

### Example
```stos
1 rem Reassign function keys. Warning! In order to get the
2 rem default assignments back, you will need to reboot STOS Basic!
10 for I=1 to 20
20 read A$
30 key (I)=A$+"'"
40 next I
50 input "Press a function key";F$
60 print "Function key number ";F$
70 goto 50
80 data "one","two","three","four","five","six","seven","eight","nine"
90 data "ten","eleven","twelve","thirteen","fourteen","fifteen","sixteen"
100 data "seventeen","eighteen","nineteen","twenty"
```
If you now run this program, and press a function key, the number of the key you pressed will be printed on the screen.

**See also:** KEY LIST, FKEY

## INKEY$
`K$=INKEY$` — Function to get a keypress.

- **K$**: the string variable which will be used to hold the key which has been pressed.

The INKEY$ function allows you to test whether a key has been pressed at any time, without having to interrupt the action of the program. If the user presses a key, then K$ will contain the Ascii character which has been input, otherwise K$ will be set to the empty string. Ascii values range from 0-255 and represent a standard code used to hold all alphanumeric characters. It is important to note that some keys, such as the cursor keys and the function keys, use a rather different format. These must therefore be read using a separate SCANCODE function.

### Example
```stos
10 while K$=""
20 K$=inkey$
30 wend
40 print "You pressed the ";K$;" Key with an Ascii code of ";asc(K$)
50 K$="" : goto 10
```

**See also:** CLEAR KEY, SCANCODE

## SCANCODE
`SCANCODE` — Input the scan code of the last key input with INKEY$.

SCANCODE is used in conjunction with INKEY$ to test whether the user has pressed a key which does not return an Ascii code. If INKEY$ detects that such a key has been input, it returns a character with the value 0. When this happens you should use the SCANCODE function to determine the internal code associated with this key.

### Example
```stos
10 while K$=""
20 K$=inkey$
30 wend
40 if asc(K$)=0 then print "You Pressed a key with no ASCII code."
50 print "The scancode is ";scancode
60 K$="" : goto 10
```

## CLEAR KEY
`CLEAR KEY` — Initialise the keyboard buffer.

Whenever you type a character on the ST's keyboard, its Ascii code is placed in an area of memory known as the keyboard buffer. It is this buffer that is read by the INKEY$ function. At the start of a program the buffer may well be full of unwanted information. It's therefore generally a good idea to remove all this garbage first using CLEAR KEY.

### Gotchas
- Buffered keypresses bleed across screens: the key that dismisses a menu, or a key held long enough for TOS auto-repeat, is still in the buffer on the next screen and can fire actions there (a menu SPACE instantly firing the ship's guns). CLEAR KEY after every keyboard wait or INPUT when changing game state.

### Example
Add line 5 to the SCANCODE example above:
```stos
5 clear key
```

**See also:** PUT KEY, INKEY$

## FKEY
`FKEY` — Read the function keys directly.

FKEY is a special form of the INKEY$ function which can be used to test the function keys directly without having to tediously use SCANCODE. Whenever a function key is pressed, FKEY returns a number between 1 and 20. Numbers greater than 10 indicate that the key has been shifted, and a value of zero means that no key has been pressed.

FKEY is often used in conjunction with ON...GOSUB to jump to one of a number of subroutines depending on a function key chosen by the user:

```text
ON FKEY GOSUB line1,line2,line3...
```

**See also:** KEY, KEY LIST

## WAIT KEY
`WAIT KEY` — Wait for a keypress.

The action of WAIT KEY is simply to halt the program until the user hits a key.

### Example
```stos
10 print "Press a key"
20 wait key
30 print "Key pressed"
```

## KEY SPEED
`KEYSPEED repeatspeed, delay` — Change key repeat speed.

- **repeatspeed**: the delay in 50ths of a second between each repeated character.
- **delay**: the time in 50ths of a second between pressing a key and the start of the repeat sequence.

This instruction allows you to tailor the speed of the keyboard to your own particular taste.

## PUT KEY
`PUT KEY a$` — Put a string into the keyboard buffer.

- **a$**: the string to load into the keyboard buffer. Carriage returns can be included using the `'` character.

This function is used to load a string of characters into the keyboard buffer. The most common use of PUT KEY is to call up a direct mode command after a program has terminated.

### Example
```stos
10 put key "new'"
```
When this line is executed, the program erases itself from the ST's memory. It does this by placing a `new` into the keyboard buffer, which is then performed directly from the editor when the program ends.

**See also:** CLEAR KEY

## INPUT
`INPUT ["prompt";] variable list` — Input a number or some text into a variable.

- **variable list**: any list of variables separated by commas.
- **prompt**: any string of characters you like.

INPUT provides you with a standard way of inputting information into a variable. When you execute an INPUT instruction, the ST displays a `?` and waits for you to enter the required information from the keyboard. If an optional prompt has been included, then this will be printed out instead of the `?`.

### Example
```text
new
10 input A
20 print A

run
? 10
10
```
If more than one variable has been specified in the list, these should be separated by a comma:
```text
new
10 input A,B,C$
20 print A,B,C$

run
? 15,40,string of characters
15 40 string of characters
```
An example with prompts:
```stos
10 input "Enter your age:";A
20 input "Enter the month, and the year of your birth:";M$,Y
30 input "Enter your christian name and surname:";C$,S$
40 print "Age = ";A
50 print "Month = ";M$;" Year = ";Y
60 print "Name = ";C$,S$
```
Sample dialogue from the third program:
```text
Enter your age:26
Enter the month, and the year of your birth:July,1961
Enter your christian name and surname:Stephen,Hill
Age = 26
Month = July Year = 1961
Name = Stephen Hill
```

### Gotchas
- The `;` between the prompt and the variables cannot be replaced by a `,`.
- Any commas input as part of a string will effectively split the string in two; use LINE INPUT if you need to enter strings containing commas.

**See also:** INPUT#, LINE INPUT

## LINE INPUT
`LINE INPUT variable list` — Input a list of variables separated by a Return.

LINE INPUT is exactly the same as INPUT, except that it uses a Return instead of a comma to separate each variable you type in.

### Example
```text
new
10 line input A,B,C$
20 print A,B,C$

run
? 10
?? 20
?? Hello
10 20 Hello
```

**See also:** INPUT, LINE INPUT#

## PRINT
`PRINT list of variables` — Print a list of variables on the screen.

- **list of variables**: any mixture of strings or numbers, separated by `;` or `,`.

The PRINT instruction has precisely the opposite effect as INPUT, and prints the contents of a list of variables at the current cursor position on the ST's screen. If a semi-colon `;` is used, then the data will be printed immediately after the last variable you output using print. If a comma is used, the cursor will be positioned a number of spaces ahead. Normally the cursor is moved downwards one line every time a print instruction is executed. This line can be suppressed by placing either of the separators at the end of the PRINT. Note that PRINT can be abbreviated to a `?`. This will be expanded in full in any program listings.

### Example
```stos
10 print "This is the story of the Hitchikers Guide to the Galaxy"
20 A=10 : B=20 : C$="Thirty"
30 print A,B;C$
40 print 10,20*10,"Hel";
50 print "lo"
```

**See also:** USING, LPRINT, PRINT#

## USING
`PRINT USING format$;variable list` — Formatted output.

- **format$**: a format string. Normal alphanumeric characters are printed as-is; the characters `~`, `#`, `+`, `-`, `.`, `;`, `^` each perform a formatting operation.
- **variable list**: the variables to print, separated by `;`.

The USING statement is used in conjunction with PRINT to provide fine control over the format of any printed output. Note the semi-colon between the format string and the list of variables.

The formatting characters are:

- `~` (Shift+#) — Formats strings. Each occurrence of `~` is replaced by a character from the following string.
- `#` — Specifies the number of digits to be printed from a numeric variable. Excess `#` characters are replaced by spaces.
- `+` — Adds a plus sign to a number if it is positive, and a minus sign if it is negative.
- `-` — Only includes a sign if the number is negative. Positive numbers are preceded by a space.
- `.` — Places a decimal point in the number, and centres it.
- `;` — Centres a number but doesn't output a decimal point.
- `^` (Shift+6) — Prints out a number in exponential form.

### Example
String formatting with `~`:
```stos
10 print using "This is a ~~~~~ demonstration of USING";"Small"
20 print using "1st Letter:~ 2nd Letter:~ 3rd Letter:~";"Basic"
```
Run output:
```text
This is a Small demonstration of USING
1st Letter:B 2nd Letter:a 3rd Letter:s
```
Digit width with `#`:
```stos
10 print using "###";314211
20 print using "# # # # #";123456
30 print using "####";56
```
Run output:
```text
4211
1 2 3 4 5
  56
```
Plus sign with `+`:
```stos
10 print using "+##";10
20 print using "+##";-10
```
Run output:
```text
+10
-10
```
Minus sign with `-`:
```stos
10 print using "-##";10
20 print using "-##";-10
```
Run output:
```text
 10
-10
```
Decimal point with `.`:
```text
print using "PI is #.###";3.1415926
PI is 3.141
```
Semicolon (centre, no decimal point):
```text
print using "PI is #;###";3.1415926
PI is 3 141
```
Exponential form with `^`:
```text
PRINT USING " Here is a number ^";12345.678
Here is a number 1.23345678E5
```

**See also:** FIX

## OPEN OUT #
`OPEN OUT #channel,file$[,attribute]` — Open a file for output.

- **channel**: a number between 1 and 10 by which the file will be referred to in all subsequent operations.
- **file$**: any string holding the name of the new file to be opened.
- **attribute**: optional file type (see DIR FIRST$).

The OPEN OUT instruction is used to open a sequential file for writing using PRINT#. If this file already exists on the disc it will be erased.

### Gotchas
- Any attempt to read a file opened by OPEN OUT will cause an error.

**See also:** CLOSE, OPEN IN, POF, LOF, EOF, PRINT#

## OPEN IN #
`OPEN IN #channel,file$` — Open a file for input.

- **channel**: a number ranging from 1 to 10 used by INPUT#, LINE INPUT# and INPUT$(#channel,count) to specify which file is to be read.

OPEN IN is used to open a file for reading. This file is only available for reading, so if you try to write to a file opened using OPEN IN, an error will occur.

**See also:** OPEN, CLOSE, INPUT#, LINE INPUT#, INPUT$(#channel,n), EOF, POF, LOF

## OPEN #
`OPEN #channel,type$,file$` — Open a channel to a random file or a device.

There are four forms of this instruction:

- `OPEN #channel,"R",file$` — Opens a random access file.
- `OPEN #channel,"MIDI"` — Opens a channel to the MIDI interface.
- `OPEN #channel,"AUX"` — Opens a channel to the RS232 port.
- `OPEN #channel,"PRT"` — Opens a channel for the printer (assumes it's plugged into the parallel port).

### Example
```stos
10 open #1,"AUX"
20 for I=0 to 10
30 print #1,"STOS BASIC"
40 next I
50 close #1
```
This program prints out ten lines of text on the device connected to the RS232 port. If your printer uses the parallel port change line 10 to:
```stos
10 open #1,"PRT"
```
Similarly you can input information from a device such as a modem with a line like:
```stos
30 input #1,A$:print A$
```
When accessing these external devices, all the normal input statements are available for your use, including INPUT$ and LINE INPUT.

**See also:** PORT, CLOSE, PUT, GET, FIELD

## CLOSE #
`CLOSE #channel` — Close a file.

- **channel**: the channel to close.

This function closes the file associated with a channel. If you forget to close a file after you have finished with it, any changes you have made to the file will be completely ignored.

### Example
```text
close #1
```

## PRINT #
`PRINT #channel,variable list` — Print a list of variables to a file or device.

- **channel**: the channel opened with OPEN OUT, OPEN, etc.
- **variable list**: same format as PRINT.

This command is identical to the normal print instruction, but instead of displaying the information to the screen, it outputs it to a file or output device specified by the channel.

### Example
```text
print #1,"Hello"
```
As with PRINT you can abbreviate PRINT# to `?#`:
```text
?#1,"Hello Again"
```

**See also:** OPEN IN, OPEN OUT, OPEN, PRINT, USING

## INPUT #
`INPUT #channel,variable list` — Input a list of variables from a file or device.

- **channel**: the channel opened with OPEN IN or OPEN.
- **variable list**: same format as INPUT.

INPUT# reads information from either a sequential file, or a device such as the MIDI interface. The format of the instruction is identical to its screen equivalent. As before it expects each piece of data in the file to be separated by a comma.

### Gotchas
- INPUT can only read up to a maximum of 500 characters worth of data at any one time. If your data is larger than this, you should always use the INPUT$ instruction instead.

## LINE INPUT #
`LINE INPUT #channel,variable list` or `LINE INPUT #channel,separator$,variable list` — Input a list of variables not separated by a comma.

This function is identical to INPUT#, but it allows you to use another character instead of a comma to separate the individual items of data on the disc. If no separator character is included, then `<Return>` is assumed.

**See also:** INPUT#, LINE INPUT

## INPUT$
`INPUT$(n)` or `INPUT$(#channel,count)` — Input n characters into a string.

- **n**: number of characters to read from the keyboard.
- **#channel**: an open input channel.
- **count**: number of characters to read from the channel.

INPUT$ has two forms. The keyboard form reads *n* characters from the keyboard, waiting for each one, and then loads them into a string. As with INKEY$, these characters are not echoed back on the screen. There is also a special version of INPUT$ which is used to access the disc: this reads *count* characters from the device or file connected to *channel*.

### Example
```stos
10 clear key
20 print "Type in ten characters"
30 C$=input$(10)
40 print "You typed in the string ";C$
```

### Gotchas
- Do not confuse INPUT$ with INPUT, as the two instructions are completely different.

## EOF #
`EOF(#channel)` — Test for end of file.

- **#channel**: an open input channel.

EOF is a useful STOS Basic function which tests to see if the end of a file has been reached at the current reading position. If it has, EOF returns a result of true, otherwise false.

## LOF #
`LOF(#channel)` — Length of open file.

- **#channel**: an open file channel.

This simply returns the length of an open file. It makes no sense to use this function in conjunction with devices other than the disc.

## POF #
`POF(#channel)` — Variable holding the current position of the file pointer.

- **#channel**: an open file channel.

The POF function changes the current reading or writing position of an open file, for example:
```text
pof(#1)=1000
```
This sets the read/write position to 1,000 characters past the start of the file. Oddly enough POF can be used in this way to provide a crude form of random access when using sequential files. The reason this works is simply that disc drives are inherently random, and all sequential operations are effectively simulated using random access.

## FIELD #
`FIELD #channel,length1 AS field1$,length2 AS field2$,...` — Define record structure.

- **channel**: channel opened with `OPEN #channel,"R",file$`.
- **lengthN**: maximum size of field *N*.
- **fieldN$**: name of the field string variable.

FIELD allows you to define a record which will be used for a random access file created using the `OPEN #channel,"R"` command. This record can consist of up to 16 alphanumeric fields and be up to 65535 bytes in length.

### Example
```text
field #1,15 as SURNAME$,15 as NAME$,10 as CODE$,10 as TEL$
```

**See also:** OPEN, GET, PUT, CLOSE

## PUT #
`PUT #channel,R` — Output record R to a random access file.

- **channel**: channel opened with `OPEN #channel,"R",file$`.
- **R**: record number to write.

PUT moves a record from the ST's memory into record number *R* of a random access file. Before use, the contents of the new record should first be placed in the field strings defined by FIELD, using a statement such as:
```text
SURNAME$="HILL"
```

### Gotchas
- Although you can write existing records in any order you like, you are not allowed to scatter records on the disc totally at random. For example, immediately after creating a file, `put #1,1` followed by `put #1,5` will generate an error, as there are no records in the file with numbers between 1 and 5.

**See also:** OPEN, GET, FIELD

## GET #
`GET #channel,R` — Input record R from a random access file.

- **channel**: channel opened with `OPEN #channel,"R",file$`.
- **R**: record number to read.

GET reads record number *R* stored in a random access file opened using OPEN. It then loads this record into the field strings created by FIELD. These strings can now be manipulated in the normal way.

### Example
```stos
10 open #1,"R","test"
20 field #1,10 as NAME$
30 I=1
40 input "Name?";NAME$
50 if NAME$="" then 90
60 put #1,I
70 inc I
80 goto 40
90 input "Record number?";R
100 if R<0 then close #1 : end
110 get #1,R
120 print NAME$
130 goto 90
```

### Gotchas
- You can only use GET to retrieve records which are actually on the disc. If you try to grab a record number which does not exist, an error will be generated.

## PORT #
`PORT(#channel)` — Function to test if a channel is waiting.

- **#channel**: an open input channel.

The PORT function tests to see if an input device connected to a channel is waiting for you to INPUT some information from it.

```text
X=PORT(#channel)
```
If the channel is ready to output some information, then X will be set to -1 (true), otherwise it will be zero (false).

## DIR
`DIR [path$] [/W]` — Print out the directory of the current disc.

- **path$**: optional path string filtering which files are displayed.
- **/W**: optional flag; if added, the files will be listed across the page.

This function lists all the files on the current disc. If the optional *path$* is specified, only the files which satisfy a certain set of conditions will be displayed. The path string can contain any of the following six parts:

- The name of a drive terminated by a `:`.
- The name of a folder to be listed (enclosed between two `\` characters).
- A string of characters which will be matched in every filename to be displayed.
- A `*` denoting that any string of up to eight characters will do.
- A `?` which automatically matches with any single character in the filename.
- A `.` which separates a filename from an extension.

### Example
```text
DIR "A:*.BAS"      : rem Lists all Basic programs on the disc.
DIR "\STOS\*.*"    : rem Lists all files in the folder STOS.
DIR "\STOS\*.CR?"  : rem Lists all the available character sets.
```

## DIR FIRST$
`DIR FIRST$(path$,flag)` — Get the first file in directory satisfying the path name.

- **path$**: the path string to search.
- **flag**: a number of binary bits indicating the type of files to be searched for.

This function returns a string containing the name and parameters of the first file on the disc which satisfies the conditions in the pathname *path$*. The format of the flag is:

- Bit 0: Normal Read/Write files
- Bit 1: Read only files
- Bit 2: Hidden files
- Bit 3: Hidden system files
- Bit 4: Volume labels (the name of the disc)
- Bit 5: Folders
- Bit 6: Files which have been written to and closed

If you aren't sure which type of files you want to list, you can find all the files on the disc by setting the flag to -1.

If no file exists on the disc matching your specifications, then DIR FIRST$ will return a null string. Otherwise it will hold the following 45-character parameter block:

| Characters | Usage |
|---|---|
| 0-12 | Filename |
| 13-21 | Length of file |
| 22-32 | Date file saved |
| 33-41 | Time file saved |
| 42-45 | File type |

**See also:** DIR NEXT$ for an example of this function in action.

## DIR NEXT$
`DIR NEXT$` — Get the next file satisfying the current path.

DIR NEXT$ returns the next file found using the path specified by DIR FIRST$. It can only be used after a DIR FIRST$ instruction has been executed. The string returned by this function is in exactly the same format as the one generated by DIR FIRST$. As before, if the string returned by the function is empty, then there are no more files in the current path.

### Example
```stos
10 input "Input path$";P$
20 N$=dir first$(P$,-1) : if N$="" then end
30 print "Files matching the path string ";P$
33 print
35 print "Names";space$(8);"Size";space$(5);"Date";space$(7);"Time";space$(5);"Type"
40 print "============================================"
50 print N$
60 repeat
70 N$=dir next$
80 print N$
90 until N$=""
```
In order to print a list of all the files on the disc, simply run this program with a path of `"*"`.

**See also:** DIR FIRST$, PREVIOUS, DIR, DIR$

## FIX
`FIX(n)` — Set the precision of printed real numbers.

FIX fixes the precision of any real numbers which are to be printed on the screen. There are three possibilities:

- If `0<n<16` then *n* denotes the number of figures to be output after the decimal point.
- If `n>16` the printout will be proportional and any trailing zeros will be removed.
- If `n<0` then all floating point numbers will be displayed in exponential format, and the absolute value of *n* (`ABS(n)`) will determine the number of digits after the decimal point.

### Example
```text

fix(-4):print PI
fix(16):print PI
```
- `fix(2)` limits the number to two digits after the point.
- `fix(-4)` forces exponential mode with four figures after the point.
- `fix(16)` reverts to the normal mode.

BIN$ generates the string of binary digits equivalent to the number *x*. As with HEX$, you can choose whether to generate all the digits or only a few.

- `X$=BIN$(x)` — Where *x* is the number to be converted to binary.
- `X$=BIN$(x,y)` — Where *x* is the number to be used, and *y* the number of digits in the string which will be loaded into *x$*. *y* can range between 1 and 31.

### Example
```text
print bin$(255)

print bin$(255,16)
%0000000011111111
```

**See also:** HEX$

## ROL
`ROL x,y` — Rotate the binary representation of *y* left by *x* places.

ROL is a Basic version of the ROL instruction from 68000 assembly language. The effect is to take the binary representation of a number in *y*, and rotate it left by *x* places.

The number 136 is represented in binary by `%10001000`. Typing `X=136` then `rol.b 1,X` gives the number 17, or binary `%00010001`. As you can see, the entire number has been shifted to the left, with the highest 1 being rotated into the lowest position. The `.b` instructs STOS to treat this number as an 8-bit byte. You can also specify the sizes `.w` (word) and `.l` (long word).

If ROL is used without `.b`, `.w`, or `.l` then `.l` is assumed. Providing you use reasonably sized numbers, ROL can be effectively considered as a very fast way of multiplying a number by a power of 2.

### Example
```text
A=1
rol 1,A
print A
2

A=32768
rol.w 2,A
print A
1
```

### Gotchas
- This procedure expects the number to be shifted to be held in a simple variable and not an expression.

**See also:** ROR

## ROR
`ROR x,y` — Rotate the binary representation of *y* right by *x* places.

ROR is similar to ROL but rotates the number in the opposite direction.

### Example
```text
A=8
ror 1,A
print A
4
```

ROR can be used as a very fast way of dividing a number by a power of two.

**See also:** ROL

## BTST
`BTST(x,y)` — Test the bit at position *x* in variable *y*.

BTST allows you to test the binary digit at position *x* in the variable *y*. If the bit at *x* is set to 1, then the value of BTST will be true, otherwise it will be false.

### Example
```text
new
10 input "Enter a number";N
20 input "Enter a bit to be tested";B
30 if B<0 or B>31 then end
40 print "Bit Number ";B
50 if btst(B,N) then print " is a one " else print "is a zero"
60 print bin$(N,32)
80 goto 10
```

### Gotchas
- As with ROR and ROL, *y* must be a single variable and not an expression.

**See also:** BCHG, BCLR, BSET

## BSET
`BSET(x,y)` — Set the bit at position *y* to 1 in variable *x*.

BSET sets the bit at position *y* to 1 in the variable *x*.

### Example
```text
A=0
bset 8,A
print A
256
```

### Gotchas
- *x* must be a simple variable rather than an expression.

**See also:** BTST, BCHG, BCLR

## BCHG
`BCHG(x,y)` — Change the bit at position *y* in variable *x*.

BCHG changes bit number *y* in the variable *x*. If this bit is currently a 1 then the new value will be a zero, and vice versa.

### Example
```text
A=0
bchg 1,A
print A
2

bchg 1,A
print A
0
```

**See also:** BTST, BSET, BCLR

## BCLR
`BCLR(x,y)` — Clear the bit at position *y* to zero in variable *x*.

BCLR sets bit number *y* in variable *x* to a zero.

### Example
```text
A=128
bclr 7,A
print A
0
```

**See also:** BTST, BSET, BCHG

## PEEK
`PEEK(address)` — Return the 8-bit byte stored at *address*.

PEEK returns the 8-bit byte stored at *address*. Technically-minded readers will be interested to note that PEEK gets information from the ST's memory while in supervisor mode. This means that you can happily type in something like:

### Example
```text
print peek(0)
```

**See also:** DEEK, LEEK, POKE

## POKE
`POKE address,x` — Load the byte at *address* with *x*.

POKE loads *address* with the number from 0–255 stored in *x*. You may use this function to change the contents of any part of the ST's memory.

### Example
```text
poke physic+1000,255
```
Pokes a blob on the ST's screen.

### Gotchas
- This function is dangerous. If you poke around indiscriminately you will almost certainly crash the ST completely.

**See also:** DOKE, LOKE, PEEK

## DEEK
`DEEK(address)` — Return the two-byte word stored at *address*.

DEEK reads the two-byte word at *address*. As with PEEK, you can use DEEK to access any part of the ST's memory including the sections that are normally inaccessible.

### Example
```text
print deek(0)
```

### Gotchas
- *address* MUST be even, or an address error will occur.

**See also:** PEEK, LEEK, DOKE

## DOKE
`DOKE address,value` — Load a two-byte word into *address*.

DOKE loads a two-byte number between 0 and 65535 into *address*.

### Example
```text
doke physic+1000,65535
```

### Gotchas
- Even the best of us make mistakes; always remember to save a copy of your programs to the disc before attempting to use this function in a new routine.

**See also:** POKE, LOKE, DEEK

## LEEK
`LEEK(address)` — Return the four-byte long word stored at *address*.

LEEK returns the four-byte long word stored at *address*. Note that if bit 31 of the contents of *address* is set, the number returned by LEEK will be negative.

### Example
```text
print leek(0)
```

### Gotchas
- Like DEEK, the *address* used with this function must always be even.

**See also:** PEEK, DEEK, LOKE

## LOKE
`LOKE address,number` — Load a four-byte long word into *address*.

LOKE loads *address* with a four-byte long word specified by *number*.

### Example
```text
loke physic+10000,$FFFFFFFF
```

### Gotchas
- Indiscriminate use of this function can lead to the ST crashing completely, so take care.

**See also:** DOKE, POKE, LEEK

## VARPTR
`VARPTR(variable)` — Return the memory address of a variable.

VARPTR returns the location in the ST's memory of a variable. Each of the different types of variables are stored in a different way:

- **Integers**: VARPTR returns the location of the value of the variable.
- **Real numbers**: VARPTR returns the location of two long words which contain the value of the variable in the IEEE double precision format.
- **Strings**: VARPTR points to the first character of the string. Since STOS Basic does not end its strings with a character 0, you must obtain the length of the string using something like `DEEK(VARPTR(A$)-2)`, where *A$* is the name of your variable. You could also use `LEN(A$)` of course.

### Example
```text
A=0
loke varptr(A),1000
print A
1000
```

## COPY
`COPY start,finish TO destination` — Copy a block of memory.

COPY rapidly moves large sections of the ST's memory from one place to another. *start* is the address of the start of the block of memory to be moved, *finish* is the address of the end, and *destination* points to the first memory location of the destination.

### Example
```text
copy logic,logic+10000 to logic+10000
```
This copies one part of the screen to another.

### Gotchas
- All these addresses MUST be even.

## FILL
`FILL start TO finish,longword` — Fill a block of memory with a long word.

FILL copies a specific long word into a section of memory. *start* is the beginning of the block and *finish* the end. *longword* is the data which will be copied into each set of four memory locations between *start* and *finish*. It is also possible to use the number of a memory BANK as the *start* or *finish* location.

### Example
```text
fill logic to logic+32000,$22334455
```
Displays a series of lines on the screen.
```text
fill 1 to 2,0
```
Fills bank 1 with 0.

### Gotchas
- If *start* and *finish* are specified as an address, these values MUST be even.

## HUNT
`X=HUNT(start TO end,a$)` — Search the ST's memory for a string.

HUNT allows you to search through the ST's memory for a specific character string. *start* is the position in the ST's memory of the start of the search, and *end* is the address of the end. On completion of this routine, X will hold either 0 (if the string in *a$* was not found) or the location of *a$*.

## WAIT
`WAIT x` — Suspend a program for *x* 50ths of a second.

WAIT suspends a STOS Basic program for *x* 50ths of a second. Any functions which use interrupts, such as MOVE and MUSIC, will continue to work during this period, with the sole exception of ON MENU GOTO.

### Example
```text
wait 50
```
This waits for one second.

## TIMER
`TIMER` — A reserved variable incremented once every 50th of a second.

TIMER is a reserved variable which is incremented by one every 50th of a second.

### Example
```text
new
10 print "Started"
20 timer=0
30 if timer<500 then goto 30
40 print "Finished"
```

**See also:** TIME$, DATE$

## NOT
`NOT(x)` — Logical NOT operation.

NOT changes every binary digit in a number from a 1 to a 0 and vice versa. Since `True=-1` and `False=0`, `NOT(True)=False`.

### Example
```text
print not(-1)
```
```text
new
10 if not(true)=false then print "False"
```

**See also:** TRUE, FALSE

## REM
`REM` — Place a remark (comment) in a program.

Any text typed in after a REM statement will be completely ignored by STOS Basic. You can therefore use this instruction to place comments at appropriate points in your programs. The apostrophe character `'` is an abbreviation for REM.

### Example
```stos
10 rem This program does absolutely nothing
```

## DATA
`DATA variable list` — Place a list of data items in a STOS Basic program.

The DATA statement allows you to incorporate lists of useful data directly inside a Basic program. This data can be loaded into a variable using the READ instruction. Each variable in the list is separated by a comma.

### Example
```stos
10 data 1,2,3,"Hello"
```

Unlike many other Basics, the STOS version of this instruction also allows you to use expressions involving variables. So the following lines of code are perfectly acceptable:

```stos
10000 data $FF50,$890
10010 data %1111111111111,%1101010101
10020 data A
10030 data A+3/2.0-sin(B)
10040 data "Hello"+"There"
```

Note that the `A` in line 10020 will be input as the contents of variable A, and not the ASCII character A. Similarly, the expression at line 10030 will be evaluated during the READ operation using the current values of A and B.

### Gotchas
- DATA must always be the only instruction on a line.

**See also:** READ, RESTORE

## READ
`READ list of variables` — Read data from a DATA statement into variables.

READ allows you to input some data stored in a DATA statement into a list of variables. It starts off with the first DATA statement in the program, and then reads each subsequent item of data in turn. As you might expect, the variable used in each READ instruction must always be of the same type as the information stored in the current DATA statement.

### Example
```text
new
10 for I=1 to 10
20 read A
30 next I
40 data 1
50 data 2,3
60 rem
70 data 4,5,6,7,8
80 data 9,10
```

Note that STOS Basic also lets you use complex expressions in a DATA statement.

### Example
```text
new
10 T=10
20 read A$,B,C,D$
30 print A$,B,C,D$
40 data "String",2,T*20+rnd(100),"STOS"+"Basic"
```

READ uses a special pointer to determine the location of the next piece of data to be input. This pointer can be changed at any time in the program using the RESTORE instruction.

**See also:** RESTORE, DATA

## RESTORE
`RESTORE line` — Set the line at which the next READ will find DATA.

RESTORE changes the line number at which a subsequent READ operation will expect to find the next DATA statement. There are two forms of this instruction:

- `RESTORE line` — Set start of DATA statements from *line*.
- `RESTORE expression` — Calculate the line number and set the read pointer to this line.

If a DATA statement does not exist at the line specified by RESTORE, an appropriate error message will be generated.

### Example
```text
new
10 restore 1000+language*10
20 read A$
30 print A$
40 end
1000 data "English"
1010 data "Francais"

francais
run
Francais
english
run
English
```

> [!NOTE] Unverified: the run sequence above is transcribed exactly as printed in the manual (francais/run/Francais, english/run/English). It does not follow from the program logic, since `restore 1000+language*10` requires `language` to hold 0 or 1. An earlier extraction silently "repaired" this to `language=0`/`language=1` and falsely claimed the scan could not be verified; the scan is perfectly legible and the fabricated reconstruction has been removed.

**See also:** READ, DATA

## TRUE
`TRUE` — Return the logical TRUE value (-1).

TRUE returns a value of -1, which is used by all the conditional operations such as IF...THEN and REPEAT...UNTIL to denote true.

### Example
```stos
10 if -1 then print "Minus 1 is TRUE"
20 if TRUE then print "and TRUE is ";TRUE
```

**See also:** FALSE, NOT

## FALSE
`FALSE` — Return the logical FALSE value (0).

Whenever a test is made such as `X>10`, a value is produced. If the condition is true then this number is -1, otherwise it is zero. The FALSE function therefore corresponds to a value of 0.

### Example
```text
print FALSE
0
```

**See also:** TRUE
